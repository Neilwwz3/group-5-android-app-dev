# 任务卡

每个任务一张卡。做任务前：

1. 先读仓库根目录的 `AGENTS.md`（项目规则）。
2. 再读自己的任务卡，看清“可以改”“不要改”和“验收标准”。
3. 用 AI 时，把 `AGENTS.md` 和任务卡一起交给 AI。Codex、Claude Code 会自动读取 `AGENTS.md`；网页版 AI 需要手动贴进对话。
4. 先切到 `dev` 并拉取最新代码，再按卡上的分支名新建分支。
5. 做完按 PR 模板向 `dev` 提 PR，在右侧 **Reviewers** 里选下表中你的审核人。
6. 审核人批准、自动编译显示绿色对勾之后，你自己点 **Merge pull request** 合并。

### 共同要求

1. **数据：** 只用 `docs/data-api.md` 里的方法，不要直接用 DAO，也不要自己建表。缺方法就找统筹。
2. **样式：** 只用视觉规范里的颜色、字号、间距和样式，布局里不写死色值。
3. **文字：** 界面上能看到的一切都用英文（包括数据里会显示的内容和日期格式），全部写进 `strings.xml`。详见 `AGENTS.md`“界面语言”一节。
4. **空状态：** 每个页面在没有数据时都要显示提示文字。
5. **PR：** 一个 PR 只做一件事，不要攒成一个大 PR。按上面的轮换表审核。

### 已定的目标

| 编号 | 目标 | 怎么验收（由负责人以外的组员在模拟器上操作） | 截止 |
| --- | --- | --- | --- |
| G7 | **联网查找影片**：添加作品时按片名在 TMDB 上查找，选中一部后自动填好片名、原名、年份、类型、题材、导演、主演、简介、片长、集数和海报，确认后保存到本机 | 模拟器联网：片库点 **+** → 搜 `dune` → 结果里有海报、片名、年份和类型 → 选 Dune: Part Two (2024) → 表单已填好，海报对得上 → 保存后片库里能看到；同一部作品不能重复添加；断网时搜索显示英文提示，手动填写照常可用 | 11 月 30 日 |

负责人和审核人在组会上定，之后统筹写任务卡。

现在的片库（G2）没有联网功能：搜索框只查本机已有的作品，添加作品要手动填写全部字段，App 也没有申请网络权限。G7 的做法要点（写任务卡时细化）：

- **和示例数据一致：** 字段来源和题材映射沿用 [D-1 任务卡](D-1-sample-data.md)的“每个字段从哪里来”和“题材映射表”，同一部作品在示例数据里和联网添加的资料一样。
- **仍然本地优先：** 只在查找时联网。保存后资料和海报都存在本机，断网也能正常使用。
- **不加第三方库：** 用 Android 自带的 `HttpURLConnection` 和 `org.json`，在后台线程请求。
- **密钥不进仓库：** TMDB 密钥从 `local.properties` 读进构建配置；没有密钥的构建（包括 GitHub 自动编译）隐藏联网查找入口，只保留手动填写。
- **要统筹先改的共享部分：** 网络权限（`AndroidManifest.xml`）、构建配置（`app/build.gradle.kts`）、按 `tmdbId` 查重的数据方法、海报从本机文件读取（`PosterLoader` 现在只读 `assets`），以及 `AGENTS.md`“隐私与版权”一节和 `docs/architecture.md` 里“无需联网”的说法。
- **注明来源：** 查找页按 TMDB 的要求显示来源署名。
